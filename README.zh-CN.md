## 这东西解决什么问题

让 AI 画一张「讲清楚这玩意怎么运作」的图,通常会得到三种失败:

- **画成了框图,不是流程**。箭头一堆,但看不出数据一步步变成了什么。
- **把设想画成了现状**。这是给领导看的材料里最伤的一种错,而且外人根本看不出来。
- **面向同行写作**。术语密集、没有铺垫,读者三行就放弃。

Flow Brief = 一套方法论 + 一个锁死的模板 + 一个「跳过方法论就不给过」的检查器。
AI 只负责填内容,**不允许重新设计版面** — 这正是产出能在不同模型、不同次运行之间
保持稳定的原因。

## 快速开始

```bash
npx skills add shaokeyibb/flow-brief
```

装完了。CLI 会自动找到你已经装了哪些 agent,然后问你装到哪儿。想直接指定的话:

```bash
npx skills add shaokeyibb/flow-brief -a claude-code
npx skills add shaokeyibb/flow-brief -a cursor
```

支持所有能读 skill 的 agent — Claude Code、Cursor、Codex、Copilot、Gemini CLI、
opencode、Windsurf、Zed 等[几十种](https://www.skills.sh/)。

然后用你平常说话的方式提要求就行:

> 给我画一张这个模块的介绍泳道图,下周要跟老板过一遍

> 新人下周入职,画个图讲讲请求从网关到数据库中间都经过了什么

> 我们打算给这条数据管线加一个重试队列,做个评审用的图,让人一眼看出哪些是现成的、哪些要新建

产出是**一个自包含的 `.html` 文件**。不用构建、不用起服务,双击就开。自带样式、
适配明暗主题、手机上也能看。

**依赖**:结构检查只要 Python 3.8+(纯标准库)。Node 和 Chrome 是可选的,
只用于额外的视口检查。

每个步骤都是同一副骨架:**吃进去什么 → 吐出来什么**,两侧各自挂着「作者凭什么知道」的
徽章,底部一条三格条回答*上游给了我什么 / 这一步产出什么 / 被谁接走*。

这条三格条**不是可选的**,检查器会强制它 — 它是绝大多数 AI 生成的图里
最缺、也最值钱的那一样东西。

## 五条规则

每条规则都对应一个具体的失败。Skill 里把「这条规则防的是什么」和规则本身写在一起 —
一条你理解其目的的规则,才能在遇到作者没预料过的情况时依然管用。

| # | 规则 | 它防住的失败 |
|---|---|---|
| 1 | **区分运行模式** | 把两种本质不同的跑法混成一条线,读者永远分不清哪些步骤每次都发生、哪些只发生过一次。**多数系统只有一种模式** — skill 明确要求 AI **不要**为了显得丰富而虚构第二种。 |
| 2 | **每个节点回答三问** | 框和箭头一堆,却看不见数据怎么流。 |
| 3 | **可信度阶梯** | 把设想画成现状。 |
| 4 | **三层阅读深度** | 面向同行写作,「30 秒版本」那一层永远没人写。 |
| 5 | **主动暴露缺口** | 通篇像宣传材料,一句「那它什么时候不好使?」就全线崩塌。 |

**第三条是真正改变工作手感的那一条**。四个档位 — **实测 / 代码事实 / 示意 / 待建** —
页面上每一格事实都必须选一档。它的价值不在于读者会来查你,而在于**你没法骗自己**:
选不出档位,就说明素材还没采够。

这也让「还没做的东西」成了一等公民:画一个尚未实现的需求时,现有的上下游标成**实测**,
新增的部分标成**待建**,而两者之间的接缝 — 风险全在那儿 — 一眼可见。

## 自检

```bash
python scripts/check_flow_brief.py out.html            # 结构检查,零依赖
python scripts/check_flow_brief.py out.html --visual   # 追加视口与主题检查
```

十二项检查。一部分是卫生问题(标签配平、markdown 语法漏进 HTML、主题只做了一半、
宽表格没包滚动容器)。真正有意思的那几项在强制方法论:每个步骤块都有三问条、
每个输入输出框都挂着出处徽章、页面至少点名一个缺口、代码事实必须给到 `file:line`
而不只是文件名。

**退出码分三档,绝不合并**:`0` 通过 / `1` 失败 / `2` **未验证**(缺 Node 或 Chrome)。
一个「什么都没检查却返回 0」的工具,比一个会失败的工具更糟 —
它会把所有人训练成相信一个毫无意义的绿灯。

两个值得一提的性质,**都是对抗性测试逼出来的,不是设计出来的**:

- **每一项检查都过了变异测试**。破坏其中一道闸,就只有那一道变红 —
  十次变异、十次命中、零串扰。一条永远不会失败的检查等于装饰品。
- **空文件会失败**。早期版本里,一个 7 行的空壳报 0 错,而一个做了一半的页面报 7 错 —
  因为「找不到步骤块」当时只是警告而非错误。**现在「什么都没有」本身就是失败**:
  这个检查器度量的是「活有没有干」,不只是「已有的部分格式对不对」。

## 目录里有什么

```
flow-brief/
├── SKILL.md                     方法论与工作流
├── templates/skeleton.html      自包含页面:CSS、主题、响应式、全部组件
├── references/
│   ├── collecting.md            怎么采素材 — 先代码,后文档
│   └── components.md            组件速查,附每个组件的坑
└── scripts/
    ├── check_flow_brief.py      结构自检(纯标准库)
    └── check_visual.mjs         可选的视口/主题检查(Node + Chrome)
```

## 说明

**唯一的网络依赖**:模板引用了 Google Fonts,所以生成的页面第一次打开时会去取三款字体。
在内网或任何不允许页面外连的场合,把 `<head>` 里那三个 `<link>` 删掉即可 —
CSS 会回落到系统字体,页面照常可读,只是没那么讲究。

**语言**:页面跟随你提问的语言。标识符、路径、命令和错误码在任何语言下都保持原样。
